## TL;DR
This file contains integration tests for the `WeftGatewayReconciler`, verifying correct tunnel creation and bastion assignment logic.

The test suite validates that the reconciler correctly translates Gateway API resources into `WeftTunnel` and `DNSRecord` CRDs. It covers protocol-specific URL semantics, ensuring HTTP listeners generate `http://` URLs, HTTPS listeners use `https://`, TCP/UDP routes use their respective schemes, and TLS passthrough uses `https://`. A critical regression test ensures routes are attached only to their specific listener (via `sectionName`) rather than creating a cross-product of all routes and listeners, which previously caused proxy conflicts. The suite also verifies bastion pinning: Layer 7 hostnames fan out to all eligible bastions, while Layer 4 hostnames are pinned to a single non-suspended bastion. If no bastion is eligible for an L4 hostname, no DNS record is created to prevent silent misrouting. Tests utilize `fakeclient` to bypass CRD validation where necessary, particularly for protocols like TCP/UDP that may have strict schema requirements in the live cluster.
